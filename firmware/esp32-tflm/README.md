# ESP32 TensorFlow Lite Micro runtime

This ESP-IDF project loads the private int8 model generated by `ml/`, registers
only its five required TensorFlow Lite Micro operators, allocates the tensor
arena in PSRAM, and exposes `ClassifyBabyMonitorCrop`.

An ESP32-S3 with PSRAM is the default target. Camera pin mappings, pixel format,
and capture APIs differ by board, so the repository deliberately keeps the
board adapter separate from the classifier. The exact board and camera module
must be known before that adapter can be implemented and verified.

## Generate, build, and flash

Generate the ignored model sources during training:

```bash
cd ml
uv run baby-monitor-edge train \
  --manifest datasets/current-view/manifest.csv \
  --frames-dir /private/path/frames \
  --output-dir artifacts/current-view \
  --generated-dir ../firmware/esp32-tflm/main/generated
```

With ESP-IDF installed:

```bash
cd firmware/esp32-tflm
idf.py set-target esp32s3
idf.py build
idf.py -p /dev/your-serial-port flash monitor
```

The model sources are private derivatives of the household images and remain
ignored by Git.

## Camera adapter contract

For each configured normalized ROI:

1. crop the camera frame;
2. convert it to one-channel grayscale;
3. resize it with bilinear interpolation to the dimensions in
   `generated/model_metadata.h`;
4. pass the contiguous bytes to `ClassifyBabyMonitorCrop`;
5. if there is more than one ROI, retain the result with the highest presence
   score.

The three boolean fields already apply the validation-selected thresholds.
Awake and pacifier are forced false when presence is false. They must remain
disabled in product behavior until their separately reported test results pass
manual validation.
